## Reproduced findings and fixes

### R1 — missing ownership marker incorrectly permitted cleanup (medium)

The fallback intended for an interrupted PID write also ran when an already
successfully written PID had later disappeared. Both deleting that marker and
replacing the lock with a new empty directory made the wrapper remove it and
report cleanup PASS. Two isolated regressions reproduced exit 0 instead of the
required 86 on the initial head. No production locks were modified in these tests.

Fix: track successfully marked locks separately. An acquired-but-never-marked
empty lock may still be rolled back on setup failure. Once a lock was marked,
missing or changed ownership evidence blocks removal and yields cleanup FAIL.
A same-user hostile replacement that forges matching evidence is still outside
this cooperative protocol; PID markers are not authentication.

### R2 — recursive chmod affected non-disposable hard-link targets (medium)

A read-only source fixture outside the run root was hard-linked inside it. The
old cleanup changed the source permission bits from 0400 to 0600 through the
shared inode. Separately, a nested directory with mode 000 could not be cleaned
by only adding write access. These were real isolated filesystem tests; no user
source was used as a fixture or changed.

Fix: non-following, preorder directory-only access repair before deletion. Do not
chmod regular files. The hard-link regression asserts preserved bytes, inode,
remaining link count and mode; the nested-directory case also asserts complete
run cleanup. Existing symlink-target and changed-owner tests remain mandatory.

## Remaining boundaries

Only compatible, cooperative foreground invocations are serialized. Detached,
unwrapped or legacy arbitrary-TMPDIR workloads are not universally controlled.
The foreground command owns its descendant lifecycle; this is not a supervisor.
SIGKILL/power loss cannot execute cleanup and leaves blocking state for inspected,
authorized recovery. No speculative process killer or automatic orphan removal
is added. Other repositories are not migrated by this review.

No further blocking finding was identified in this bounded source review after
these corrections; final readiness still requires successful exact-head checks.
Owner merge authorization remains separate.
