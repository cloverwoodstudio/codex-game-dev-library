## Findings and repairs

1. **Silent link discovery failure.** The old rg invocation supplied no search
   path. A Linux sandbox reproduction with installed ripgrep 14.1.1 and one
   Markdown URL produced exit 1 with empty stdout/stderr under an empty input
   pipe; adding an explicit path found the file and exited 0. `/dev/null` also
   searched files successfully. Thus stdin type matters; the historical CI log
   alone did not record it. The replacement enumerates tracked Markdown through
   Git with explicit paths and never reads stdin. A child-process regression
   exercises an empty pipe and unrelated working directory.
2. **Missing rg on the Mac.** Previous local checking failed with exit 127. The
   replacement needs only already-present Python/Git/curl. No install is needed.
3. **False negative HEAD responses.** The first live pass found 314 page URLs in
   129 Markdown files: 306 HTTP successes, four restrictions and four HEAD 404s.
   Direct GET then returned 200 for the three Google help pages and a redirect
   for OWASP. The checker now verifies rejected HEAD responses with bounded GET
   and revalidates redirects. No source URL was silently exempted. A subsequent full pass confirmed the obsolete OWASP subpath still returned 404; its four references were updated to the official project page, whose content was independently reviewed.
4. **Missing diagnostics.** Every live result records URL, source files/lines,
   HTTP code and classification. Missing inventory, malformed paths/URLs,
   transport failures and hard HTTP failures cannot become a silent PASS.

## HTTP safety and limits

Only credential-free HTTP(S) links to ports 80/443 are accepted. Local/private
address literals and DNS results are rejected. The checked address is pinned for
each request; redirects are handled explicitly and rechecked, not delegated to
unrestricted curl following. User curl configuration and proxy inheritance are
disabled. No cookies, tokens or document contents are sent. Requests have time,
redirect and GET size limits, plus at most one reported retry for transport/server
failure. Hard HTTP failures are not retried until a lucky success. DNS resolution still depends on the host resolver;
this checker is not a general untrusted-network sandbox or availability monitor.

The pre-existing 401/403/429 non-blocking policy is preserved with explicit
RESTRICTED / not-verified output. A policy PASS does not mean every link or every
page's content was verified. Anchor validity and semantic relevance are not
checked. There is no ignore-all-errors switch or per-URL bypass list.
