# Onboarding, tutorials and objective clarity

Reviewed: 2026-08-29

Teach the smallest action immediately before it becomes useful: demonstrate, let the player act, confirm the result, then combine it with prior knowledge. A controls poster is reference material, not a tutorial.

## Knowledge map

List each concept with prerequisite, teaching moment, safe practice, mastery check, reminder and recovery hint. Separate mandatory concepts from optional depth. Instrument tutorial states as normal gameplay states so they can be tested and revisited.

## Teaching loop

1. Establish a clear short-term objective.
2. Present one relevant action using the player's current input glyph.
3. Allow unhurried practice with low failure cost.
4. Acknowledge the correct outcome through more than one sensory channel.
5. Remove the prompt only after demonstrated understanding.
6. Reuse the action in a meaningful challenge.

Do not freeze the game to explain an action the player cannot yet contextualize. Avoid prompt spam, forced repetition after mastery and irreversible penalties during first exposure.

## Accessibility and returnability

Make objectives and progress reviewable at any time. Tutorials should be replayable or available on demand, with subtitles for voiced instruction. Support remapped controls, narration-friendly text, readable language, adjustable timing and non-audio/non-color-only cues. Offer reminders after long absence without resetting progress.

## Measurement

Track where players hesitate, repeat, fail, skip, abandon or open help. Define success as demonstrated behavior and later retention, not merely closing a popup. Observe players without coaching; analytics cannot reveal a misunderstood mental model by itself.

Test keyboard/mouse, controller, touch and accessibility configurations separately. Verify changed bindings update every prompt and tutorial video/reference.
