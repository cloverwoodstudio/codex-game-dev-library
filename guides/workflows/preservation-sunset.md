# Preservation and service sunset

Reviewed: 2026-08-29

Plan for the day development stops. Preservation is partly technical, partly contractual and legal; this guide is not legal advice and does not authorize bypassing licenses or access controls.

## Preservation package

Retain source and history, exact toolchain/engine installers where licensing permits, dependency locks/source, build scripts, CI definitions, signing history, source assets, import settings, schemas/migrations, server/protocol documentation, symbols, release binaries/manifests, licenses/provenance, manuals, patch notes and representative gameplay captures.

Document hardware/OS/API expectations, controls, locales, known defects and a verified clean-build procedure. Use open, documented formats for durable metadata and export critical proprietary data when practical. Verify backups through restoration, not file counts.

## Online dependency map

List authentication, matchmaking, game servers, cloud saves, economy, telemetry, moderation, CDN, time/config and third-party APIs. For each, define player impact if unavailable and whether an offline/local/read-only fallback is technically, contractually and legally possible.

## Sunset sequence

1. Inventory dependencies, obligations and affected player data.
2. Freeze risky economy/content changes and publish a dated communication plan.
3. Provide export/refund/transfer paths where required.
4. Release a final stable build and migration/offline mode if authorized.
5. Disable purchases before value can no longer be delivered.
6. Wind down services in dependency order and verify deletion/retention commitments.
7. Preserve documentation, artifacts and gameplay evidence with an appropriate institution or owner.

The Library of Congress recommended-formats material recognizes software/games and notes that video of use can provide evidence when playable preservation is unavailable. Captures supplement; they do not replace a runnable build and technical documentation.
